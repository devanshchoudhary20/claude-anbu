# 12 · DSA Light

Panel: FAANG phone screens and one onsite round; India product companies round 1. Frontend loops ask medium, rarely hard, with a bias to arrays, strings, hash maps, trees, recursion, and the occasional graph. Interleaved from week 2: one problem a week, 45 minutes, in `src/js/dsa/`. The interviewer wants a stated approach, complexity, and a clean implementation with tests, more than the optimal trick.

Ledger items: `arrays-two-pointers`, `hash-map-patterns`, `strings`, `stack-queue`, `recursion-backtracking`, `trees-dfs-bfs`, `graphs-basic`, `sorting-searching`, `dp-light`, `frontend-flavoured`.

## Weekly problem pool, in order

1. Two sum, three sum, container with most water. Two pointers.
2. Group anagrams, top K frequent, longest substring without repeat. Hash map and sliding window.
3. Valid parentheses, min stack, daily temperatures. Stack.
4. Flatten nested list, generate parentheses, subsets. Recursion and backtracking.
5. Max depth, level order, lowest common ancestor, serialize a tree. DFS and BFS.
6. Number of islands, clone graph, course schedule. Graphs.
7. Merge intervals, binary search on answer, kth largest. Sorting and searching.
8. Climbing stairs, coin change, longest increasing subsequence. DP light.
9. Frontend-flavoured: LRU cache (then say where React uses one), trie for autocomplete, event throttling with a queue, topological sort of a task dependency graph, virtual DOM diff of two trees, flatten a nested comment thread, compute the DOM path between two nodes.
10. Mock round: two unseen mediums in 45 minutes.

## Follow-ups

- "Complexity. Can you do better. What is the space cost of your better."
- "Now the input does not fit in memory."
- "Write the test that breaks it."

## Pass bar

Nine weeks of problems done with tests and stated complexity. The frontend-flavoured set is fully done. Mock round: both solved with the approach stated in the first five minutes.
